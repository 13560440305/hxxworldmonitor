## 0. 先分清四个概念

管理后台里容易混淆的对象：

| 概念 | 存哪 | 是什么 | 不是什么 |
|------|------|--------|----------|
| **数据源配置** | `integration_providers` | 第三方 API / 披露站点的 **Base URL + 加密 API Key** | 不是用户勾选的「邮件套餐」 |
| **采集引擎** | `engines` | 通用抓取能力凭证（如 Firecrawl） | 不是业务数据源本身 |
| **采集绑定** | `data_source_ingest_bindings` | 数据源 ↔ 引擎 ↔ ingest 插件 | — |
| **可订阅项** | `subscription_presets` | 邮件产品模板（规则 + 语言） | 与数据源**无一一对应表** |

**一句话：** 数据源告诉系统「怎么连外部服务」；可订阅项告诉用户「能订什么邮件」。二者数量不同是正常的（源 10+，默认套餐 4）。

```text
外部 API / 站点 / RSS
        │
        ▼
 integration_providers（凭证） ──绑定──► engines（Firecrawl 等）
        │                                    │
        │                              ingest 插件执行
        ▼                                    ▼
  仪表盘 /api 实时拉取              news_items / 公告 / KG
                                            │
                                            ▼
                               subscription 匹配 → 邮件
                               （规则来自 subscription_presets）
```

## 1. 配置原则（现行策略）

| 原则 | 说明 |
|------|------|
| **密钥尽量进 DB** | Admin「数据源 / AI 模型」写入 PG；仅存 `base_url` + 加密 `api_key`（及 AI 的 `model_name`）；具体 URL path 写死在代码 |
| **环境变量兜底** | catalog 声明的 `envApiKey` / `envBaseUrl` 在 DB 为空时仍可读 `.env.local` |
| **基础设施仍用 env** | `DATABASE_URL`、JWT、端口、OSS、`VITE_*`、Upstash、Relay 进程自身密钥等 |
| **全部可选降级** | 未配置 Key 时对应面板/图层隐藏或空数据；RSS、地震等核心能力可无 Key 运行 |
| **密钥配置** | Admin「数据源 / AI 模型」写入 PG；未配时可用 `.env.local` 兜底 |

尚未完全迁入 DB 的示例：Relay/Telegram 进程变量（`AISSTREAM_*`、`TELEGRAM_*` 等）——见 `.env.example` 注释。

## 2. 内置 integration_providers（业务数据源目录）

启动时按 catalog **seed**。Admin 可改 URL/Key/启用状态。

### 2.1 平台与 AI

| slug | 分类 | 用途 | 环境变量兜底 |
|------|------|------|----------------|
| `hxxbot` | platform | 发信、翻译、问答（`builtin.email_send` 等） | `HXXBOT_API_KEY` / `HXXBOT_API_URL` |
| `groq` | ai | 云端 LLM 摘要 | `GROQ_API_KEY` |
| `openrouter` | ai | LLM 备选路由 | `OPENROUTER_API_KEY` |
| `ollama` | ai | 本地 OpenAI 兼容端点（Key 可选） | `OLLAMA_API_URL` / `OLLAMA_API_KEY` / `OLLAMA_MODEL` |

### 2.2 市场 / 宏观 / 能源

| slug | 分类 | 用途 | 环境变量兜底 |

| `fred` | market | 美联储 FRED 宏观序列 | `FRED_API_KEY` |
| `eia` | energy | 美国能源统计 | `EIA_API_KEY` |
| `wto` | market | 贸易与关税 | `WTO_API_KEY` |

### 2.3 地缘 / 环境 / 军事 / 航空 / 网络安全

### 2.4 中继与披露

| slug | 分类 | 用途 | 环境变量兜底 |
|------|------|------|----------------|
| `relay` | relay | 自托管 WS 中继（AIS / OpenSky / RSS / Telegram 聚合） | `WS_RELAY_URL` + `RELAY_SHARED_SECRET` |
| `cninfo` | disclosure | 巨潮资讯网站点根 URL（**无官方数据 API Key**） | 无；抓取靠 Firecrawl 绑定 |

`cninfo` 备注：在「采集引擎」配置 Firecrawl，并在数据源上绑定插件 `cninfo-disclosure`；接口路径硬编码在插件内。

### 巨潮披露要点（CN Phase 1）

- 主数据：`listed_companies` / `listed_securities`；公告幂等键 `(workspace_id, source, source_doc_id)`  
- KG：`company —filed→ filing`，正文规则抽 `subsidiary` / `shareholder` / `controller` 等  
- 解析降级：HTTP → Firecrawl → pdf-parse  
- Admin：披露统计、失败重采入队；前端图谱可「抽取关系」

## 5. 仪表盘实时源（多数不经 PG Worker）

下列源主要由 **`/api/*` sebuf / 代理** 按需拉取，与邮件订阅无直接映射。面板级说明见 [DOCUMENTATION.md](./DOCUMENTATION.md)。

### 5.1 通常无需 API Key

| 类别 | 来源示例 |
|------|----------|
| 新闻 | ~100–150 个 RSS/Atom 域名（经 `rss-proxy` / Relay） |
| 地缘 / 事件 | UCDP、GDELT、NGA 海事警告 |
| 灾害 | USGS 地震、NASA EONET、GDACS、Open-Meteo |
| 市场 | Yahoo Finance（非官方）、CoinGecko、Polymarket、Fear & Greed、blockchain.info |
| 航空 | OpenSky（匿名限额紧；生产建议 Relay + OAuth） |
| 威胁 | Feodo、部分 URLhaus/OTX/C2 公开源 |
| 人道 / 人口 | UNHCR、WorldPop、World Bank、HDX（可选标识） |
| 其他 | FAA、USASpending、Hacker News、ArXiv、GitHub（Token 可选） |

### 5.2 需要 Key（与 §2 catalog 重叠者优先走 Admin/DB）

ACLED、Finnhub、FRED、EIA、NASA FIRMS、Groq、OpenRouter、Cloudflare Radar、AbuseIPDB、Wingbits、AviationStack、ICAO、WTO、URLHaus、OTX、HXXBOT、Relay 等——详见 §2。

可选：`GITHUB_TOKEN`、`HDX_APP_IDENTIFIER`、Upstash Redis（跨用户缓存）、`CONVEX_URL`（注册）、`VITE_SENTRY_DSN`。

### 5.3 自托管 Relay 专属

进程：`scripts/ais-relay.cjs`（文档 [AIS-RSS-RELAY.md](./AIS-RSS-RELAY.md)）。

| 变量组 | 用途 |
|--------|------|
| `WS_RELAY_URL` / `VITE_WS_RELAY_URL` / `RELAY_SHARED_SECRET` | 前端/API 连中继 |
| `AISSTREAM_API_KEY` | AIS 船舶 |
| `OPENSKY_CLIENT_ID` / `OPENSKY_CLIENT_SECRET` | OpenSky OAuth |
| `TELEGRAM_API_ID` / `HASH` / `SESSION` / `TELEGRAM_CHANNEL_SET` | Telegram OSINT 频道 |
